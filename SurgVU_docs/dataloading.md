# V-JEPA2.1 SurgVU Training Dataloading

This document describes the actual dataloading path used when training the V-JEPA2.1 SurgVU configs in this repository, especially `configs/train_2_1/vitb16/surgvu-finetune-384px-16f.yaml`.

The relevant code path is:

```text
app/main.py
  -> app.scaffold.main(app="vjepa_2_1")
  -> app/vjepa_2_1/train.py
  -> src/datasets/data_manager.py:init_data()
  -> src/datasets/video_dataset.py:make_videodataset()
  -> src/datasets/video_dataset.py:VideoDataset
  -> src/masks/multiseq_multiblock3d.py:MaskCollator
```

## High-level Flow

1. `app/main.py` reads the YAML config and launches one process per selected GPU, or a single process in debug mode.
2. `app/vjepa_2_1/train.py` reads the `data`, `data_aug`, and `mask` sections.
3. `train.py` builds a `MaskCollator` before constructing the dataloader.
4. `train.py` builds the video transform with `app.vjepa_2_1.transforms.make_transforms()`.
5. `train.py` calls `init_data(...)`, passing the manifest path list, frames-per-clip list, requested training FPS, transform, distributed rank information, sampler weights, and mask collator.
6. `init_data()` dispatches `dataset_type: VideoDataset` to `make_videodataset()`.
7. `make_videodataset()` constructs `VideoDataset`, chooses a distributed sampler, and wraps both in a PyTorch `DataLoader`.
8. Each training iteration calls `next(loader)`, receiving one or more frame-count groups, each containing clips and masks.
9. The training loop moves clips and masks to the device, then passes clips to the target encoder and passes the same clips plus encoder masks to the context encoder/predictor path.

## SurgVU Config Inputs

The main SurgVU fine-tuning config currently sets:

```yaml
data:
  dataset_type: VideoDataset
  datasets:
  - data/surgvu/manifest_train.csv
  datasets_weights:
  - 1.0
  batch_size: 8
  crop_size: 384
  patch_size: 16
  dataset_fpcs:
  - 16
  tubelet_size: 2
  fps: 4
  filter_long_videos: null
  filter_short_videos: false
  preprocess_metadata: data/surgvu/preprocess_metadata.json
  use_preprocess_metadata: true
  video_backend: ffmpeg
  length_weighted_sampling: true
  num_workers: 8
  persistent_workers: true
  pin_mem: true
```

Important meanings:

| Key | Effect |
| --- | --- |
| `datasets` | One or more space-delimited manifest files. |
| `datasets_weights` | Dataset-level sampling weights. This triggers weighted sampling even if there is only one dataset. |
| `batch_size` | Per-rank batch size. Global batch is `batch_size * world_size`. |
| `dataset_fpcs` | Frames per clip for each manifest in `datasets`. For SurgVU this is `[16]`. |
| `fps` | Target temporal sampling rate. For 60 FPS videos and `fps: 4`, the loader samples about every 15 source frames. |
| `crop_size` | Final training crop size after random resized crop. |
| `patch_size` | Spatial ViT patch size. With `384` and patch size `16`, each frame has a `24 x 24` token grid. |
| `tubelet_size` | Temporal patch size. With `16` frames and tubelet size `2`, the model has `8` temporal token steps. |
| `filter_long_videos` | Maximum source video file size in bytes. `train.py` converts `null` to `1e18`, effectively disabling the upstream 1 GB default. |
| `filter_short_videos` | If `true`, rejects videos or valid segments shorter than the requested clip span. SurgVU uses `false`, so short clips are padded by repeating the last available frame. |
| `preprocess_metadata` | Per-video crop and black-section metadata generated by `scripts/preprocess_surgvu_videos.py`. |
| `use_preprocess_metadata` | Enables metadata-aware crop/black-interval logic. If this is `null`, `train.py` enables it automatically whenever `preprocess_metadata` is set. |
| `video_backend` | `ffmpeg` uses metadata-aware ffmpeg frame extraction when possible, otherwise falls back to Decord. |
| `length_weighted_sampling` | Samples longer usable videos more often, after subtracting black intervals when metadata is available. |
| `num_workers` | DataLoader workers per process. |
| `persistent_workers` | Keeps worker processes alive across loader iterations when `num_workers > 0`. |
| `pin_mem` | Enables pinned CPU memory for non-blocking GPU transfer. |

## Manifest Format

`VideoDataset` expects each row to contain a path and a label:

```text
/absolute/or/relative/path/to/video.mp4 3
```

For SurgVU self-supervised V-JEPA2.1 training, the label is not used by the loss. It is still read, returned by the dataset, and collated because the generic `VideoDataset` API expects it. `scripts/prepare_surgvu.py` creates stable numeric labels from the dominant task label per case only to satisfy this loader contract.

The loader also accepts `.npy` path lists. The SurgVU configs use CSV manifests.

## Dataset Construction

`VideoDataset.__init__()` performs these steps:

1. Validates that exactly one of `fps`, `duration`, or `frame_step` is provided. SurgVU uses `fps`.
2. Normalizes a single manifest path into a list.
3. Builds `dataset_fpcs`. If `dataset_fpcs` is unset, every dataset uses `frames_per_clip`; SurgVU explicitly sets `[16]`.
4. Reads each `.csv` manifest with a space delimiter and appends column 0 to `samples` and column 1 to `labels`.
5. Records per-dataset sample counts and constructs `ConcatIndices`, which maps a global sample index back to `(dataset_index, sample_index_within_dataset)`.
6. If `use_preprocess_metadata` is true, loads every provided `preprocess_metadata.json` and indexes each video entry by both original and resolved source paths.
7. Builds optional `sample_weights`.

For SurgVU, `sample_weights` are present because `length_weighted_sampling: true` and `datasets_weights: [1.0]` are configured.

## Length-weighted Sampling

When length weighting is enabled, each video's raw weight is its usable duration:

```text
usable_duration = video_duration - total_black_interval_duration
```

The duration comes from metadata in this order:

1. `duration`
2. `source_frames / source_fps`
3. `written_frames / output_fps`

Black intervals come from:

1. `black_sections_removed`, if present and non-empty
2. otherwise `black_sections_detected`

This is important for metadata-only preprocessing: even if no cleaned video is written and `black_sections_removed` is empty, detected black intervals can still reduce sampling weight and constrain clip sampling.

After raw duration weights are computed for a dataset, they are normalized within that dataset and multiplied by the corresponding `datasets_weights` entry.

## Sampler Choice

`make_videodataset()` chooses the sampler as follows:

- If `dataset.sample_weights` exists, it uses `DistributedWeightedSampler`.
- Otherwise it uses `torch.utils.data.distributed.DistributedSampler`.

For SurgVU fine-tuning, the active sampler is `DistributedWeightedSampler`.

`DistributedWeightedSampler`:

- samples indices with replacement using `numpy.random.Generator.choice`
- uses probabilities from `dataset.sample_weights`
- seeds its RNG with `seed + epoch`
- returns the rank-local slice of the sampled global index list

When `optimization.ipe` is set, `train.py` passes `num_batches_per_epoch=(ipe * num_epochs)` into `init_data()`. The weighted sampler receives `num_samples_per_replica = num_batches_per_epoch * batch_size`, so its generated per-rank sample stream can be larger than one epoch. The training loop still consumes only `ipe` batches per epoch.

## DataLoader Construction

With `deterministic: true` or when the key is omitted, `make_videodataset()` constructs a normal PyTorch `DataLoader`:

```python
torch.utils.data.DataLoader(
    dataset,
    collate_fn=mask_collator,
    sampler=dist_sampler,
    batch_size=batch_size,
    drop_last=True,
    pin_memory=pin_mem,
    num_workers=num_workers,
    persistent_workers=(num_workers > 0) and persistent_workers,
)
```

If `deterministic: false`, it uses `NondeterministicDataLoader`, a subclass that can return completed worker batches out of order. The SurgVU config does not set `deterministic`, so the normal ordered DataLoader is used.

There is no custom worker initialization function in this path. Sampler order is epoch-seeded, but clip start, random crops, flips, and mask details still use worker-local random state during loading/collation.

## Video Sample Loading

For each sampled index, `VideoDataset.__getitem__()`:

1. Reads `sample = self.samples[index]`.
2. Routes image paths (`.jpg`, `.png`, `.jpeg`) to `get_item_image()`.
3. Routes all other paths to `get_item_video()`.
4. If loading fails, randomly selects another dataset index and tries again until a sample loads.

SurgVU uses video paths, so the normal route is:

```text
__getitem__()
  -> get_item_video()
  -> loadvideo_decord()
```

The method name `loadvideo_decord()` is historical. It can use either ffmpeg or Decord:

- If `video_backend: ffmpeg` and metadata contains frame count, FPS, and crop geometry, `_loadvideo_ffmpeg_metadata()` tries to decode only the requested frames and crop them in ffmpeg.
- If ffmpeg is unavailable, metadata is incomplete, ffmpeg loading fails, or `video_backend` is not `ffmpeg`, it falls back to Decord `VideoReader`.

## Temporal Sampling

For SurgVU:

```text
frames_per_clip = 16
target fps = 4
typical source fps = 60
frame step = int(source_fps) // target_fps = 15
clip_len = frames_per_clip * frame_step = 240 source frames
```

So a normal 16-frame clip spans about:

```text
240 / 60 = 4 seconds
```

The exact source frame indices are selected by `_sample_video_indices()`.

### With Preprocess Metadata

If metadata has black intervals, the loader converts black intervals from seconds to source-frame intervals and builds valid non-black frame segments.

For each requested clip:

1. A valid segment is selected.
2. If `random_clip_sampling` is true, the segment is selected with probability proportional to segment length.
3. If the segment is longer than `clip_len`, a random contiguous source-frame window of length `clip_len` is selected inside that segment.
4. `np.linspace(start, end, num=frames_per_clip)` produces the 16 source frame indices inside that window.
5. Indices are clipped to valid source-frame bounds.

This means a training clip never intentionally crosses a detected black interruption when metadata is available.

### Without Valid-segment Metadata

If no metadata black intervals are available, the loader samples from the full video:

1. `sample_len = num_frames`
2. `partition_len = sample_len // num_clips`
3. for each clip partition, choose a random `clip_len` source-frame window when the partition is long enough
4. otherwise sample what exists and repeat the last available frame as needed

`train.py` does not pass `num_clips`, so the default is `1`.

### Short Videos Or Short Valid Segments

If a video or valid segment is shorter than `clip_len`:

- with `filter_short_videos: true`, the sample is rejected
- with `filter_short_videos: false`, the loader samples available frames and repeats the last frame until `frames_per_clip` frames are returned

The SurgVU config sets `filter_short_videos: false`.

## Spatial Crop From Metadata

When metadata provides:

```text
crop_x
crop_y
crop_width
crop_height
```

the decoded frame buffer is cropped deterministically before V-JEPA data augmentation. This removes static black margins and overlay regions detected during preprocessing.

The crop is applied to the raw decoded buffer shaped:

```text
[T, H, W, 3]
```

and returns:

```text
[T, crop_height, crop_width, 3]
```

This crop is separate from the later random resized crop to `crop_size x crop_size`.

## Frame Buffer Transform

After frames are decoded and metadata crop is applied:

1. `get_item_video()` splits the flat decoded buffer into `num_clips` clips.
2. Each clip is passed through `app.vjepa_2_1.transforms.VideoTransform`.
3. The transform converts the clip to float tensor form.
4. It permutes from `[T, H, W, C]` to `[C, T, H, W]`.
5. It applies random resized crop, using:
   - `random_resize_scale`
   - `random_resize_aspect_ratio`
   - `motion_shift` when enabled
6. It applies horizontal flip with probability `0.5` when enabled. `train.py` always calls `make_transforms(random_horizontal_flip=True, ...)`.
7. It normalizes in place with ImageNet mean and std in 0-255 scale when `auto_augment: false`.
8. It applies random erasing only when `reprob > 0`.

For the current SurgVU fine-tuning config, the effective augmentation is:

```text
random resized crop to 384 x 384
horizontal flip p=0.5
ImageNet normalization
```

because `auto_augment: false`, `motion_shift: false`, and `reprob: 0.0`.

Each returned transformed clip has shape:

```text
[C, T, H, W] = [3, 16, 384, 384]
```

## Dataset Return Value

For a video sample, `get_item_video()` returns:

```python
(
    buffer,        # list of transformed clips, length num_clips
    label,         # manifest label, not used by self-supervised loss
    clip_indices,  # list of source-frame index arrays, one per clip
)
```

For the current SurgVU training path:

```text
num_clips = 1
buffer[0].shape = [3, 16, 384, 384]
len(clip_indices[0]) = 16
```

## Mask Collation

`MaskCollator` is used as the DataLoader `collate_fn`. It does more than stack tensors; it also creates V-JEPA encoder and predictor masks.

Construction:

```python
MaskCollator(
    cfgs_mask=cfgs_mask,
    dataset_fpcs=dataset_fpcs,
    crop_size=crop_size,
    patch_size=patch_size,
    tubelet_size=tubelet_size,
)
```

For each frames-per-clip value, it creates one `_MaskGenerator` per YAML mask block.

For SurgVU:

```text
frames_per_clip = 16
tubelet_size = 2
crop_size = 384
patch_size = 16
temporal tokens = 16 / 2 = 8
spatial tokens = 384 / 16 by 384 / 16 = 24 x 24
total video tokens per sample = 8 * 24 * 24 = 4608
```

The fine-tuning config has two mask generators:

1. small prediction blocks: `num_blocks: 8`, `spatial_scale: [0.15, 0.15]`, `temporal_scale: [1.0, 1.0]`
2. large prediction blocks: `num_blocks: 2`, `spatial_scale: [0.7, 0.7]`, `temporal_scale: [1.0, 1.0]`

During collation:

1. Samples are grouped by actual frames-per-clip.
2. PyTorch `default_collate()` stacks each group.
3. For each mask generator, `_MaskGenerator(batch_size)` returns:
   - `masks_enc`: token indices kept as encoder context
   - `masks_pred`: token indices predicted by the predictor
4. The collator returns one tuple per frames-per-clip group.

For the normal single-FPC SurgVU config, a loader batch has one group:

```python
[
    (
        collated_batch,
        collated_masks_enc,
        collated_masks_pred,
    )
]
```

where:

```text
collated_batch[0][0].shape = [B, 3, 16, 384, 384]
collated_batch[1].shape    = [B]              # labels
collated_batch[2][0].shape = [B, 16]          # source frame indices
len(collated_masks_enc)    = number of mask blocks in YAML, 2 for SurgVU
len(collated_masks_pred)   = number of mask blocks in YAML, 2 for SurgVU
```

`_MaskGenerator` samples one block size per collator step using a seed derived from its internal counter, then samples block locations per sample. It trims every sample in the batch to the minimum number of kept encoder and predictor tokens so masks can be stacked into dense tensors.

## Batch Consumption In The Training Loop

The training loop consumes a collated batch as:

```python
sample = next(loader)

all_clips = []
all_masks_enc = []
all_masks_pred = []

for fpc_sample in sample:
    udata, masks_enc, masks_pred = fpc_sample
    all_clips += [udata[0][0].to(device, non_blocking=True)]
    all_masks_enc += [[m.to(device, non_blocking=True) for m in masks_enc]]
    all_masks_pred += [[m.to(device, non_blocking=True) for m in masks_pred]]
```

For single-FPC SurgVU training:

```text
clips = [tensor of shape [B, 3, 16, 384, 384]]
masks_enc = [[mask_0, mask_1]]
masks_pred = [[mask_0, mask_1]]
```

The list wrapper matters because the model supports mixed frame counts and image/video rank splits. SurgVU uses only one video frame-count group.

## What The Model Sees

For each iteration:

1. `target_encoder(clips, gram_mode=False, training_mode=True)` receives unmasked normalized clips.
2. `encoder(clips, masks_enc, gram_mode=False, training_mode=True)` receives the same clips plus encoder-context masks.
3. `predictor(z, masks_enc, masks_pred, mod="video")` predicts target features for masked predictor-token locations.
4. The prediction loss compares predictor outputs against target-encoder features gathered at `masks_pred`.
5. If `predict_all: true`, the context loss also compares context predictions against target features gathered at `masks_enc`.

With the current config:

```text
loss_exp = 1.0
predict_all = true
weight_distance_loss = true
lambda_value_vid = 0.5
lambda_progressive = true
```

So dataloaded clips feed both the masked prediction objective and the dense/context objective.

## Epoch And Loader Behavior

`train.py` initializes the loader once:

```python
unsupervised_sampler.set_epoch(start_epoch)
loader = iter(unsupervised_loader)
```

Inside each epoch, it consumes exactly `ipe` batches. If the iterator is exhausted:

1. it logs that dataloaders are exhausted
2. it calls `unsupervised_sampler.set_epoch(epoch)` for normal datasets
3. it recreates the iterator

Each batch load has retry handling. Non-`StopIteration` dataloading exceptions are retried up to five times with a five-second sleep. After that, training raises an error.

## Practical Debugging

Use the dataloader preview script to inspect the actual training inputs:

```bash
python scripts/visualize_surgvu_dataloader.py \
  --config configs/train_2_1/vitb16/surgvu-finetune-384px-16f.yaml \
  --num-batches 5 \
  --max-samples 4 \
  --frames-per-row 8 \
  --batch-size 4 \
  --num-workers 0 \
  --seed 239 \
  --disable-augment
```

This script uses the same `VideoDataset`, transform path, temporal sampling, metadata crop, and `MaskCollator` as training. Its contact sheets show denormalized frames plus source-frame indices, which is the fastest way to verify that metadata cropping and black-interval avoidance are working before launching a long run.

## Key Consequences For SurgVU

- Labels are loader metadata only; the self-supervised V-JEPA2.1 loss does not use them.
- A normal training sample is a 16-frame, 4 FPS clip spanning about 4 seconds of source video.
- Metadata-aware training reads original videos, avoids detected black intervals, applies deterministic crop geometry, then applies normal V-JEPA random spatial augmentation.
- `length_weighted_sampling: true` makes longer usable SurgVU clips appear more often.
- `video_backend: ffmpeg` avoids decoding unnecessary frames when metadata is complete, but Decord remains the fallback.
- The collator creates masks at token resolution, not pixel resolution. For 384px/16f/tubelet2 training, each sample has 4608 video tokens before masking.
- `pin_mem: true` and `.to(device, non_blocking=True)` are paired so host-to-GPU transfer can overlap when the runtime supports it.
